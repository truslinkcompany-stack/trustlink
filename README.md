# ДоброСлед

**Веб-сервис, который превращает фотографию с телефона в проверяемое подтверждение выполненной работы.**
Время, координаты и контрольная сумма файла фиксируются сервером в момент съёмки. В результате получается PDF-сертификат с QR-кодом и публичная страница проверки.

Статус: **Фаза 1, прототип (v0.1)**. Сайт: см. переменную `NEXT_PUBLIC_SITE_URL` в настройках Vercel.

## О проекте

Сейчас НКО и социальные проекты подтверждают работу фотографиями с ручными подписями (дата, место). Такое подтверждение нельзя проверить: данные внутри файла легко изменить, а подпись остаётся лишь заявлением. Отчётность перед грантодателями отнимает много времени, а фотоматериалы разбросаны по мессенджерам и папкам.

ДоброСлед делает обычное фото проверяемым. Сервис **не заменяет отчётность фонда**: он улучшает раздел «подтверждающие документы».

**Для кого:** НКО и социальные проекты России и СНГ, их полевые сотрудники и волонтёры; фонды и организации, которые проверяют отчёты.

**Модель:** на этапе пилота сервис бесплатен для НКО, коммерческая модель определяется позже.

## Как это работает

1. Сотрудник открывает ссылку на телефоне и разрешает камеру и геолокацию.
2. Снимает фото камерой на странице (загрузки готового файла из галереи нет). Снимок сжимается до JPEG на устройстве.
3. При желании указывает проект, имя автора и комментарий. Пустые поля в сертификат не попадают.
4. Сервер сохраняет файл в закрытое хранилище, фиксирует **своё** время (UTC), считает SHA-256 и записывает данные в базу. Время телефона хранится отдельно и помечено как непроверенное.
5. Человек получает страницу результата с фото, номером сертификата (`DS-2026-1012-003`), QR-кодом и PDF.
6. Проверяющий сканирует QR и открывает `/verify/{id}`. Сервер заново считает хеш сохранённого файла и показывает **«ПОДТВЕРЖДЕНО»** или **«НЕ ПОДТВЕРЖДЕНО»**.

## Известные ограничения

Мы раскрываем их пользователям (в сертификате, на сайте и в статьях):

- Координаты предоставляет браузер устройства, их можно подменить специальными программами. Сервис показывает заявленную точность, но не гарантирует защиту от подмены.
- Сертификат подтверждает, что файл получен сервисом в указанное время и не менялся с этого момента. Поля «Проект», «Автор» и «Выполнено» заполнены пользователем и не проверяются.
- Сервис **не определяет**, создано ли изображение нейросетью, и не отличает настоящее событие от инсценировки.
- Ограничение «только камера» работает в интерфейсе сервиса. Технически подготовленный файл можно отправить напрямую в API, поэтому ограничение снижает риск, но не исключает его.
- Съёмка без интернета в прототипе недоступна.
- Лица людей на фото относятся к персональным данным: не снимайте людей крупным планом без согласия.

## Критерии приёмки KPI № 1 (прототип)

- [ ] Весь путь от фото до PDF проходит без ручных правок.
- [ ] Время в сертификате отличается от реального не больше чем на минуту; точка совпадает с реальным местом в пределах заявленной точности (на улице не больше 100 м).
- [ ] Сервис не принимает готовый файл из галереи, только камеру.
- [ ] QR, ссылка и PDF открываются и читаются на iPhone и Android; при сканировании QR открывается сертификат.
- [ ] 5 тестовых сертификатов, минимум на одном iPhone и одном Android.
- [ ] «Подтверждено» для корректных записей и «Не подтверждено» для несуществующих идентификаторов.
- [ ] Оригинал фото недоступен по публичной ссылке.
- [ ] Есть страницы «О проекте» и «Новости».

## Технологии

- **Next.js 15** (App Router, TypeScript), React 19
- **Supabase**: PostgreSQL и закрытое файловое хранилище (bucket `photos`)
- **Vercel**: хостинг
- **pdf-lib + @pdf-lib/fontkit** (PDF, шрифт Noto Sans с кириллицей), **qrcode**, **sharp**
- Шрифт интерфейса: Inter (`@fontsource-variable/inter`)
- Геокодирование (название места): OpenStreetMap Nominatim

## Структура репозитория

```
app/
  page.tsx, capture.tsx      главная и съёмка (камера, геолокация, форма)
  result/[id]/               страница результата: фото, QR, PDF
  verify/[id]/               публичная страница проверки по QR
  about/, news/              «О проекте» и новости
  api/records/               приём файла, хеш, запись в базу
  api/records/[id]/pdf/      генерация PDF (нужен токен создателя)
  api/geocode/               название места по координатам
  sitemap.ts, robots.ts      SEO
components/                  переключатель темы, блок «При поддержке»
content/news/*.md            статьи (markdown)
lib/                         словарь текстов, форматы, PDF, Supabase, токены
public/                      шрифты, логотип, картинки статей, og.png
supabase/schema.sql          схема базы (выполнить один раз)
```

## Быстрый старт (локально)

1. **Supabase.** Создайте проект и выполните `supabase/schema.sql` в SQL Editor. Если уже запускали старую версию схемы, выполните `supabase/migration_002.sql`.
2. Скопируйте `.env.example` в `.env.local` и заполните значения (таблица ниже).
3. Установите зависимости и запустите:
```bash
   npm install
   npm run dev
```
4. Откройте `http://localhost:3000`.

Камера и геолокация работают только по **HTTPS** или на `localhost`. Чтобы проверить на телефоне, откройте адрес развёрнутого сайта на Vercel (локальный адрес вида `http://192.168...` браузер блокирует).

Проверка типов: `npm run lint` (запускает `tsc --noEmit`).

## Переменные окружения

| Переменная | Обязательно | Описание |
| --- | --- | --- |
| `SUPABASE_URL` | да | Адрес проекта, `https://xxxx.supabase.co`, без `/rest/v1` |
| `SUPABASE_SECRET_KEY` | да | Секретный ключ Supabase. Только на сервере |
| `PDF_TOKEN_SECRET` | да | Секрет для ссылок на PDF и результат. `openssl rand -hex 32` |
| `NEXT_PUBLIC_SITE_URL` | да | Адрес сайта. Попадает в QR сертификатов, после выбора домена не менять |
| `SHOW_PHOTO_ON_VERIFY` | нет | `true`: показывать фото на публичной странице проверки (по умолчанию нет) |
| `NEXT_PUBLIC_SHOW_PARTNERS` | нет | `true`: блок «При поддержке» (нужны логотипы в `public/partners/`) |
| `GOOGLE_SITE_VERIFICATION`, `YANDEX_VERIFICATION` | нет | Коды подтверждения для поисковых систем |

Старые имена `NEXT_PUBLIC_SUPABASE_URL` и `SUPABASE_SERVICE_ROLE_KEY` тоже читаются, но как запасные.

## Новости и тексты

- Статья это файл `content/news/ГГГГ-ММ-ДД-название.md`. Имя файла без `.md` становится адресом.
- Шапка: `title`, `date`, `summary` между строками `---`. Дальше текст в markdown: заголовки `##` и `###`, списки `-`, таблицы, `**жирный**`, `[ссылки](/путь)`, картинки `![описание](/news/файл.png)`.
- Картинки кладите в `public/news/`.
- Тексты интерфейса: `lib/dict.ts`. Включённые языки: `ENABLED_LANGS` в том же файле (сейчас только русский; английский словарь сохранён на будущее, узбекский добавляется по аналогии).

## Безопасность и данные

- Фото хранятся в **закрытом** bucket; публичной ссылки на оригинал нет, доступ только по временным подписанным ссылкам.
- Записи **неизменяемы** (append-only): триггер в базе запрещает изменение и удаление.
- Ключи доступа используются только на сервере. Скачать PDF (в нём миниатюра фото) и открыть результат может только создатель записи по ссылке с токеном.
- Ограничения: JPEG, до 5 МБ, ограничение числа запросов с одного адреса (для пилота заменить на общее хранилище, например Upstash).
- Собираем минимум данных: фото, время, координаты, устройство и необязательные поля, введённые пользователем.
