# ДоброСлед: структура проекта и контекст

Этот файл для разработчика и для ИИ-ассистента. Он объясняет, что делает каждый файл, как данные проходят через систему и какие решения принимались и почему. Описание продукта, этапов и запуска: см. `README.md`.

## Что это

Веб-сервис для НКО. Сотрудник снимает фото камерой на странице, сервер фиксирует своё время, координаты устройства и SHA-256 файла, создаётся PDF-сертификат с QR-кодом. По QR любой человек открывает страницу проверки. Сейчас: Фаза 1 (прототип), интерфейс только на русском.

**Стек:** Next.js 15 (App Router, TypeScript) + React 19, Supabase (PostgreSQL + закрытое хранилище), Vercel, pdf-lib, qrcode, sharp. Шрифт Inter. Название места: OpenStreetMap Nominatim.

## Как данные проходят через систему

**Создание записи.** `capture.tsx` снимает кадр из `<video>` в canvas, сжимает до JPEG (до 1920 px, до ~3,5 МБ) → POST `/api/records` (multipart). Сервер: ограничение запросов → проверка полей → проверка JPEG по сигнатуре байтов и размера (≤5 МБ) → SHA-256 → геокодирование (сервер определяет место сам) → загрузка файла в bucket `photos` → вставка в `records` → ответ `{id, cert_no, token}`. Если вставка в БД не удалась, загруженный файл удаляется. Клиент переходит на `/result/{id}?t={token}`.

**Страница результата.** Проверяет токен, берёт запись, создаёт временную ссылку на фото (10 минут), рисует QR на `/verify/{id}`. Кнопка PDF открывается в новой вкладке.

**PDF.** `/api/records/{id}/pdf?t=...&lang=ru`: проверка токена → запись → скачивание файла из хранилища → `buildCertificate` → ответ `inline`.

**Проверка.** `/verify/{id}`: запись → скачивание файла → пересчёт SHA-256 → сравнение с сохранённым. Фото показывается только при `SHOW_PHOTO_ON_VERIFY=true`.

**Новости.** `news.ts` читает markdown, `markdown.tsx` рисует. Страницы статей генерируются при сборке.

**Язык и тема.** Тексты в `dict.ts`. Тема хранится в cookie `theme` и применяется скриптом в `<head>` до отрисовки.

## База данных (`supabase/schema.sql`)

Таблица `records`: `id` (uuid), `cert_no` (`DS-ГГГГ-ММДД-NNN`), `created_at` (время сервера), `client_time`, `client_tz`, `lat`, `lng`, `accuracy_m`, `place_name`, `device`, `sha256`, `file_path`, `project_name`, `author_name`, `description` (три необязательных поля), `user_agent`, `status` (`valid`/`revoked`).

- RLS включён, публичным ролям доступа нет: работает только сервер с секретным ключом.
- Триггер `records_immutable` запрещает UPDATE и DELETE даже серверу (append-only).
- Bucket `photos`: закрытый.

## Решения и причины

- **Время берёт сервер**, время телефона хранится отдельно как непроверенное.
- **Хеш считает сервер** по принятым байтам.
- **Фото в закрытом bucket**: публичной ссылки на оригинал нет. Миниатюра в PDF и фото на странице результата доступны только создателю по токену.
- **PDF-шрифт встраивается целиком** (`subset: false`): с подмножеством шрифта Noto Sans в PDF пропадали буквы.
- **Сжатие на телефоне**: у Vercel есть лимит размера запроса (~4,5 МБ).
- **Место определяет и клиент (для показа), и сервер (для записи)**: клиенту не доверяем.
- **`ENABLED_LANGS`**: английский словарь сохранён на будущее, сейчас включён только русский. Добавление языка: словарь в `dict.ts` + элемент в `ENABLED_LANGS`.
- **Статические страницы**: язык и тема не читаются из cookie на сервере (пока один язык), поэтому главная, «О проекте» и новости статические, быстрее и лучше для поисковиков.
- **Имена переменных Supabase**: `lib/supabase.ts` читает `SUPABASE_URL` и `SUPABASE_SECRET_KEY` (их создаёт интеграция Vercel), старые имена как запасные. Адрес очищается до `origin`.
- **Логотип с белым фоном**: в светлой теме фон «растворяется» через `mix-blend-mode`, в тёмной логотип обесцвечивается и светлеет.

## Как внести типичные изменения

| Задача | Что менять |
| --- | --- |
| Изменить текст | `lib/dict.ts` |
| Добавить язык | словарь в `lib/dict.ts` + `ENABLED_LANGS` |
| Новая статья | файл в `content/news/`, картинки в `public/news/` |
| Новое поле формы | `capture.tsx`, `api/records/route.ts`, новая миграция SQL в `supabase/`, `lib/supabase.ts` (тип), `lib/pdf.ts`, `verify/[id]/page.tsx`, тексты в `dict.ts` |
| Показывать фото на странице проверки | переменная `SHOW_PHOTO_ON_VERIFY=true` |
| Включить блок партнёров | логотипы в `public/partners/` + `NEXT_PUBLIC_SHOW_PARTNERS=true` |
| Сменить домен | `NEXT_PUBLIC_SITE_URL` + Redeploy. Адрес в уже выданных QR не изменится, сохраните старый домен |

## Грабли

- После изменения переменных в Vercel нужен **Redeploy**. Переменные с `NEXT_PUBLIC_` вшиваются при сборке.
- Камера и геолокация работают только по **HTTPS** или `localhost`.
- Переменную в Vercel типа Secret нельзя прочитать после сохранения и нельзя поменять на обычную: при ошибке создавайте заново.
- Ограничение запросов хранится в памяти процесса, на Vercel оно неточное; для пилота заменить на Upstash.
- Nominatim (OpenStreetMap) ограничивает частоту запросов: для большого потока нужен платный провайдер.
- При скачивании файлов повторно браузер дописывает `(1)` к имени: проверяйте имена картинок.
- Список выданных сертификатов с QR на старом домене нужно держать рабочим.

## Правила для ИИ-ассистента

- Отвечать по-русски. Код давать **полными файлами** с путём, а не фрагментами «вставьте сюда».
- Перед ответом запускать мысленно `npx tsc --noEmit`: тип `Record` в `dict.ts` общий для `ru` и `en`, любой новый ключ нужно добавлять в **оба** словаря.
- **Не нарушать append-only**: не добавлять UPDATE/DELETE записей.
- **Не доверять клиенту**: время, хеш, место для записи считает сервер.
- **Не обещать то, чего сервис не делает**: он не определяет ИИ-изображения, не гарантирует точность координат, не проверяет текст полей. Ограничения нужно раскрывать честно (грантовое требование «disclose known limitations»).
- **Не светить секреты**: ключи и `PDF_TOKEN_SECRET` не вставлять в код, чат и коммиты.
- Не добавлять на сайт английский или другой язык без решения команды: сейчас только русский.
- Бренд везде «ДоброСлед» (латиницей `dobrosled`). Название TrustLink не использовать.
- Данные пользователей: минимум; вопросы 152-ФЗ, согласия и политики решаются юристом, готовые тексты добавлять по запросу.
